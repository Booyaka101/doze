# Doze Friday Close demo

## Disclosure shown throughout

Synthetic exports. Recorded Gemma mapping, not live inference. Actual running
application interactions. No account access, payment or public upload.

## Storyboard, roughly 75 seconds

| Beat | Action | Caption |
| --- | --- | --- |
| 1 | Show the app and synthetic sources | Teach the job once. Then let the AI sleep. |
| 2 | Click recorded Gemma lesson; show its origin badge | This is saved output from a real local Gemma call, not a new call. |
| 3 | Review mapping and run witnesses | A mapping must survive known failures, not just look plausible. |
| 4 | Show eight passing tests | Eight fixed studio cases. Expected answers are not model-generated. |
| 5 | Reconcile messy week | One cent short, a duplicate transfer, an orphan. Handoff blocked. |
| 6 | Inspect source records | Exact references and decimal arithmetic, not a model's judgment. |
| 7 | Reuse mapping for next clean week | Same mapping, next week, inference still disabled. |
| 8 | Review packet controls | Approval binds this exact report. Source exports stay unchanged. |
| 9 | Run the synthetic year | 1,248 payments. 41 clean weeks, 11 held. Zero model calls. |
| 10 | Show replay detail and conclude | The artifact keeps working after the model's job is done. |

The demo must not hide the recorded-result disclosure or describe the synthetic
year as real customer use. No new inference call is needed to make this asset.
Current exact live-teaching evidence is close-grounded-teaching.json.

## Produced asset

`evidence/doze-friday-close.mp4`: 68.53 seconds, silent H.264 MP4, approximately
1.94 MB. Actual running application captured in 62 sampled browser frames, encoded
at 15 fps while preserving elapsed timing. This is not a 15-fps source recording
and not a live inference demonstration. Editorial captions identify the distinction
throughout. `evidence/close-entry-demo.json` contains timings and successful checks.
The viewport is 1440x1080 CSS pixels; Windows capture produced 2160x1620 encoded
pixels. `submission/demo-contact-sheet.jpg` shows six frames extracted from MP4.

All seven recording assertions passed. The first capture completed the app flow
but failed an unnecessarily high frame-count threshold before encoding. One
corrected capture produced the delivered asset; there were no model retries.
Intermediate frames are isolated under ignored `.doze/close-capture-*` directories.

## Production

Use only the local Doze tab, not the whole desktop. Capture actual interactions
at normal speed; no replacement result cards or invented counters. Caption overlay
is editorial, explicitly separate from application UI. Save local MP4, capture
timings and checks. A frame-sampled capture should be described as such, not as a
high-frame-rate screen recording. No narration or music is required.
